# Environment variables

Generated by `julia scripts/env-vars.jl` and checked in CI; do not edit by hand.

## Settings

Everything Gesso reads at run time. Most advanced switches sit under the three
lists at the bottom, whose items are comma separated; names are case-insensitive
and spaces around items are ignored. A `GESSO_TUNE` value that does not parse is
an error.

    GESSO_DISABLE=prefill_window,quant_simd
    GESSO_PROFILE=decode,expert=/tmp/experts.tsv
    GESSO_TUNE=dq_gemm_min=64,hot_mib=480

| Variable | Default | Meaning |
|---|---|---|
| `GESSO_BACKEND` | `lava` | Backend for the scripts and the chat server: `lava`, `cpu` (the correctness oracle), `cuda` (comparator), `amdgpu` (chat server, GPU-untested). |
| `GESSO_KV_FORMAT` | per backend | KV cache format: `f32`, `f16`, `q8` or `q4h`. Unset is `q8` on CUDA, `q8` on Lava below 512 tokens of context and `f32` from 512. |
| `GESSO_GPU_BUDGET_MIB` | free memory less the reserve | Device memory for weights, in MiB. Unset probes free memory; 4800 when the probe is unavailable. |
| `GESSO_GPU_BUDGET_CTX` | 65536 | Context length the weight budget keeps KV room for. A server's `--n-ctx` wins. |
| `GESSO_GPU_RESERVE_MIB` | 1024 | Least device memory kept free for KV, prefill passes and the desktop, in MiB. |
| `GESSO_PREFILL_CHUNK` | 1024 | Largest prefill pass, in rows. |
| `GESSO_CTX_CHECKPOINTS` | 8 | Prompt checkpoints kept per session for prefix reuse; 0 keeps only the end-of-prompt snapshot. |
| `GESSO_CTX_CHECKPOINT_EVERY` | 512 | Tokens between context checkpoints. |
| `GESSO_CPU_POOL_THREADS` | Julia threads, at most 18 | Worker threads in the CPU kernel pool, capped at the Julia thread count. |
| `GESSO_PIN_THREADS` | on for multi-node | `1` pins pool workers to cores, `0` never does. Unset pins only on a multi-node box. |
| `GESSO_NUMA` | on for multi-node | `1` makes node-local weight copies, `0` never does. Unset copies only on a real multi-node topology. |
| `GESSO_NUMA_NODES` | sysfs | Fake NUMA nodes as `;`-separated cpulists (`0-8;9-17`), for testing the multi-node paths on one socket. |
| `GESSO_LAVA_CPU_ORDER_QUANT` | `1` | `1` makes Lava's quant kernels sum in CPU order, so Lava matches the CPU path bit for bit. `0` takes the faster subgroup kernels. |
| `GESSO_DISABLE` | empty | Comma-separated list of default-on paths to turn off. See below. |
| `GESSO_PROFILE` | empty | Comma-separated list of diagnostics to turn on. See below. |
| `GESSO_TUNE` | empty | Comma-separated `key=value` tuning overrides. See below. |

Backend `all` means the CPU path and every GPU backend.

## GESSO_DISABLE

| Name | Backend | Turns off |
|---|---|---|
| `gdn_prefill_gnorm` | CUDA | Fused gated-norm in GatedDeltaNet prefill. |
| `gdn_recur_reg` | CUDA | Register-resident GatedDeltaNet recurrence kernel; falls back to the shared-memory kernel. |
| `gguf_read` | all | Reading the GGUF into memory at load; falls back to the mmap. |
| `gpu_dense_quant` | CUDA | Quantized dense GEMV/GEMM on the device; falls back to dequant-to-F16. |
| `hot_experts` | CUDA, Lava | Device pool of frequently used host experts (on by default on CUDA, opt-in on Lava). |
| `hot_pin` | CUDA | Pinned host staging for the hot-expert pool. |
| `hot_prefill` | CUDA | Hot-expert planning during prefill. |
| `moe_device_prefill` | CUDA | Batched device MoE prefill; falls back to the per-token loop. |
| `moe_device_route` | CUDA | Router top-k on the device; falls back to the host route. |
| `moe_host_experts` | AMDGPU, CUDA, Lava | Routed experts kept on the host. Lava and AMDGPU require it. |
| `moe_overlap` | CUDA, Lava | Shared expert overlapped with the routed-expert copies. |
| `moe_prefill_route` | CUDA | Device routing during MoE prefill. |
| `precompile_workload` | all | The precompile workload run while Gesso precompiles. |
| `prefault` | all | Prefaulting GGUF weight pages at load. |
| `prefill_multi` | all | Multi-row quant prefill kernels on the CPU. |
| `prefill_window` | all | Windowed prefill; falls back to the per-row prefill. |
| `quant_simd` | all | SIMD quant kernels on the CPU; falls back to the scalar kernels. |
| `rope_table_cache` | Lava | Cached RoPE tables on Lava. |
| `window_fused` | Lava | Fused sliding-window attention on Lava; falls back to the per-head path. |

## GESSO_PROFILE

| Name | Backend | Turns on |
|---|---|---|
| `decode` | all | Per-op decode timing. `GESSO_PROFILE=1` means `decode`. |
| `expert` | CUDA | `expert=PATH` writes expert usage counts to PATH. |
| `hot_stats` | Lava | Hot-expert pool hit statistics when the pool is released. |
| `prefill` | all | Per-op prefill timing. |
| `routing` | all | `routing=PATH` writes the per-token routing trace to PATH. |
| `timing` | all | Per-token generate timing. |

## GESSO_TUNE

| Key | Default | Backend | Meaning |
|---|---|---|---|
| `cpu_order_wg_max` | per kernel | Lava | Largest workgroup for Lava's CPU-order kernels; `0` keeps the thread-per-row kernels. |
| `cpu_pool_spin_us` | 200 | all | Microseconds a CPU pool worker spins before it sleeps. |
| `cuda_expert_cache` | `0` | CUDA | `1` turns on the CUDA device expert cache. |
| `cuda_expert_cache_mib` | auto | CUDA | CUDA expert cache size, in MiB. |
| `cuda_weight_dtype` | `f16` | CUDA | Device dtype of large CUDA weights: `f16` or `f32`. |
| `dq_gemm_min` | `32` | CUDA, Lava | Fewest tokens for which a quant matmul takes the dequant GEMM instead of the GEMV. |
| `dq_gemm_scratch_mib` | `32` | CUDA, Lava | Dequant GEMM scratch buffer, in MiB. |
| `expert_cache` | `0` | all | Host expert slices kept dequantized; `0` is off. |
| `gemv_chunks_per_thread` | 16 | all | CPU GEMV work chunks per thread. |
| `gemv_pool` | `auto` | all | CPU GEMV scheduler: `auto`, `pool` or `threads`. |
| `gguf_unreorder_v` | `0` | all | `1` gathers tiled V heads into grouped order at load. |
| `hot_decay` | `0.99` | CUDA | Decay of the hot-expert usage score per token. |
| `hot_fill` | `2` | CUDA | Experts the hot pool loads per token. |
| `hot_margin` | `1.0` | CUDA | Score margin an expert needs to replace a resident one. |
| `hot_mib` | auto | CUDA, Lava | Hot-expert pool size, in MiB. |
| `hot_prefill_expert_us` | `70.0` | CUDA | Per-expert launch cost the prefill planner assumes, in µs. |
| `hot_prefill_gbps` | `6.5` | CUDA | Host-to-device bandwidth the prefill planner assumes, in GB/s. |
| `hot_prefill_headroom_kib` | `768` | CUDA | Device headroom the prefill planner keeps, in KiB. |
| `hot_prefill_keep` | no limit | CUDA | Most hot experts kept through a prefill. |
| `hot_prefill_max_seq` | `4096` | CUDA | Longest prefill the hot-expert planner handles (max 65535). |
| `hot_prefill_pair_us` | `45.0` | CUDA | Per token-expert pair cost the prefill planner assumes, in µs. |
| `hot_prefill_round` | `16` | CUDA | Token rounding of hot-expert prefill segments. |
| `hot_prefill_seg` | `1024` | CUDA | Tokens per hot-expert prefill segment. |
| `hot_prefill_stream` | `32` | CUDA | Experts the prefill planner streams per segment. |
| `lava_hot_experts` | `0` | Lava | `1` turns on the hot-expert pool on Lava. |
| `moe_device_prefill_chunk` | `512` | CUDA | Tokens per launch group in device MoE prefill. |
