# Spark 2.5 port (Spark-X2.6-4B) — receipt

Status: CPU oracle path landed on `claude/spark2-5-20261022`. The paged
`Session` does not run this family yet; it refuses Spark plans by name.

## What the model needs

Spark-X2.6-4B, GGUF arch `spark2_5`, read from the GGUF header:

| Field | Value |
|---|---|
| layers / hidden / ffn | 36 / 2560 / 10240 |
| heads / KV heads / head_dim | 16 / 4 / 256 |
| vocab | 131072, tied embeddings |
| attention | fused QKV, per-head sigmoid gate (`g_proj`) before `o_proj` |
| window | 512 on SWA layers, pattern `[SWA, SWA, SWA, full] × 9` |
| RoPE | full layers θ = 5e6 over 64 dims; SWA layers θ = 1e4 over the whole head; NEOX layout |
| FFN | GEGLU with exact (erf) GELU |
| tokenizer | byte-level BPE, pre `spark2_5`, bos 0, eos 1 |

Four things here were new to Gesso: a sliding-window mask, per-layer
RoPE, a per-head attention gate, and GEGLU.

## Changes

* `ArchitectureSpec` gains `sliding_window`, `swa_layers` and
  `rope_swa`, with `layer_window(spec, l)` and `layer_rope(spec, l)`.
  Construction rejects a `swa_layers` vector whose length is not
  `num_layers`.
* `gguf_import.jl` maps `spark2_5` header keys and tensors, including the
  fused QKV split and the `attn_gate` tensor as `attention.head_gate`.
* `semantic_params.jl` adds the `attention.head_gate` role
  (`:wattn_head_gate`); `materialize_architecture.jl` shapes it
  `(n_heads, hidden)` and adds per-block `:attn_window`, `:rope_layer`
  and `:ffn_geglu` slots only for families that declare them, so other
  families keep their block layouts.
* `Inference.jl` `reference_prefill` and the CPU decode path apply the
  window mask, the block's own RoPE and the head gate.
  `_attention_decode_cpu!` takes `window`.
* `cpu_linear.jl` adds `_cpu_erf`, `_cpu_gelu_erf` and `_cpu_geglu!`
  (stdlib only, no SpecialFunctions; see below).
* `gguf_tokenizer.jl` adds the `spark2_5` pre-tokenizer split.
* `backends.jl` declares `:sliding_window_attention`, `:geglu_ffn` and
  `:attn_head_gate`; `import_report.jl` adds `:geglu` and `:gelu` to the
  activation axis and `[:attn_head_gate]` to the feature axis of the
  conformance matrix.
* `gguf_quant_matrix.jl` adds native F16 and BF16 matmul. Each weight
  row is widened once and dotted with every token: 16 lanes per token as
  two explicit `<8 x float>` vectors (`Base.llvmcall`), four tokens per
  pass, rows threaded. From 257 tokens up, row chunks are widened into
  F32 and run as one BLAS GEMM, which is faster there (measured
  crossover: the row dot wins at 128 tokens, 30 ms vs 52 ms; GEMM wins
  at 512). A row's result does not depend on the thread split or on how
  many tokens share the call, so a token alone matches the same token
  inside a prefill bit for bit. Before this, both types went through the
  ggml `to_float` bridge on every call.
* The CPU reference attention (`_attention_scores_cpu!`,
  `_attention_values_cpu!`) loops over contiguous key and value columns
  and splits query rows across threads. Every score and output element
  keeps the same accumulation order as the old triple loops, so the
  bit-exact decode contract in `cpu_decode.jl` still holds.
* `session.jl` errors on any block that carries `:wattn_gate`,
  `:wattn_head_gate`, `:attn_window`, `:rope_layer` or `:ffn_geglu`,
  instead of running it wrong.

## GELU accuracy

The first erf used a short rational fit. Its left-tail error against
MPFR was 1.1e-13 relative, which comes from `1 + erf` cancelling. The
landed version uses a Maclaurin series below |x| = 2, the erfc continued
fraction from 2 to 6, and computes the far-left GELU tail from erfc
directly, with `exp(-x²/2)` split so the rounding of `x²` never reaches
the exponent. Against MPFR on −37..8 in 0.01 steps plus edge points:
erf absolute error ≤ 2.4e-16, GELU relative error worst case 3.6e-15
near x ≈ −1.77 (just right of the erfc switch). `test/test_spark25.jl`
pins both bounds.

## Parity against llama.cpp

The oracle is `llama-server` (llama.cpp with the `spark2_5` arch, CPU,
`-ngl 0`) on the BF16 GGUF. It gives the first-token top-10 logprobs and
a 32-token greedy completion. Gesso runs `reference_prefill` for the
first-token distribution and `reference_generate` for the greedy
continuation, on the same token ids.

| Prompt | Tokens | Top-1 | max \|Δ logprob\| over llama top-10 | Greedy match |
|---|---|---|---|---|
| p1 | 5 | same (19500) | 0.035 | 32/32 |
| p2 | 18 | same (74288) | 0.070 | 32/32 |
| long | 992 | same (3769) | 0.048 | 32/32 |

`long` is longer than the 512-token window, so 27 of the 36 layers mask
keys and the two RoPE bases both carry weight. A wrong mask or a swapped
RoPE would show up there first. The remaining logprob difference is
within the gap between the tanh GELU in llama.cpp and the erf GELU here,
plus the different accumulation order. Ranks swap only between
near-ties (at most 0.06 apart in either run).

The parity numbers above are the same before and after the native BF16
kernel and the threaded CPU attention: same top-1 tokens, same max |Δ|
to five places, 32/32 greedy on every prompt.

Oracle timings on this machine (CPU reference path, not a serving path):

| | `to_float` bridge, serial attention | native BF16 + threaded attention |
|---|---|---|
| `long` prefill, 992 tokens (`reference_prefill`) | 1446 s | 121.6 s |
| `p2` prefill, 18 tokens | 8.83 s | 2.53 s |
| decode at 1k context | about 8.5 s/token | 1.03–1.12 s/token |
| `p2` 32-token generate | 223.4 s | 29.1 s |

The new decode figure comes from `GESSO_TIMING=1` on the `long` prompt
(the prefill inside `reference_generate` took 117 s). Each step splits
about evenly between attention (0.48–0.55 s) and FFN (0.55–0.57 s). In
the parity run the 32-token `long` generate took 330.8 s, about 180 s
more than prefill plus 32 timed steps. Other jobs were loading the
machine during that run, and I have not pinned the gap down. Load is
4.9 s once the file is in the page cache (10.2 s cold).

Hardware: Xeon E5-2699 v3 (18 cores, 36 threads), 31 GB RAM, Julia `-t 16`.
Peak RSS for the parity run was 8.8 GB.

## Follow-ups landed with the port

* qwen35 GGUFs without `output.weight` (Qwen3.5-0.8B) now load with a
  tied head. The spec builder hard-coded `tie_word_embeddings=false` and
  both Qwen35 adapters always required `output.weight`.
* `reference_prefill(...; hidden=true)` returns the final-normed hidden
  states `(dim, seq)` and skips the head. PSNCM uses it to build latents
  from the transformer instead of from the raw embedding table.

## Limitations

* The KV cache is sized to the context, not the window. A 512-slot ring
  buffer for SWA layers is future work; it would cut KV memory for 27
  of the 36 layers.
* Paged `Session` refuses this family (see above). Spark runs through
  `reference_generate` (CPU, with a decode KV cache) only. At about
  1 s per token that is a correctness path, not a serving path.
  Session support (window, per-layer RoPE, head gate, GEGLU in the
  fused step) is the next piece of work.
* The exact GELU runs a 120-step continued fraction for the tail. That is
  fine for the oracle and too slow for a fast path; a fused kernel would
  use a minimax fit checked against this one.
* llama.cpp uses the tanh GELU approximation for this arch, so it is not
  bit-for-bit the same reference as Hugging Face's `gelu`. Parity numbers
  above include that difference.
